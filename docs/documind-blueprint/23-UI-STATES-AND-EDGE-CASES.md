## 2. Domain A: Document Upload Edge Cases (`EC-001` – `EC-009`)

| ID | Scenario | 1. What Happens & 2. Why It Happens | 3. Application Response | 4. What the User Sees | 5. Data Preserved | 6. Retry? | 7. Admin Needed? |
|---|---|---|---|---|---|---|---|
| **`EC-001`** | **Corrupted / Truncated PDF** | File has `.pdf` extension, but internal XRef table or stream is broken (e.g. incomplete browser download). | `fitz.open()` catches `FileDataError` in Stage 1 validation (`<15ms`) and rejects with `422 ERR_PDF_CORRUPTED`. | Red inline upload card: *"File appears corrupted and cannot be opened. Please check the original PDF and try again."* | Other valid files in a multi-file upload batch continue unaffected. | User can re-upload a valid copy. | No |
| **`EC-002`** | **Empty / 0-Byte or 0-Page PDF** | User uploads a 0-byte file or a blank PDF with 0 pages or 0 extractable content and 0 images. | Stage 1 checks `file_size == 0` or `doc.page_count == 0`; Stage 6 checks if total extracted + OCR characters == 0. | **`EC-003`** | **Password-Protected / Encrypted PDF** | Corporate or bank PDF requires a user/owner password to decrypt streams (`doc.is_encrypted == True`). | Stage 1 detects `doc.needs_pass` immediately and returns `422 ERR_PDF_PASSWORD_PROTECTED`. | *"This PDF is password-protected. Please unlock or print-to-PDF without a password before uploading."* | Zero storage or OpenAI tokens consumed. | Yes, after unlocking PDF. | No |
| **`EC-004`** | **Extremely Large PDF (> 50 MB or > 300 Pages)** | User attempts to upload a 180 MB scanned encyclopedia or 1,200-page manual. | Client dropzone + FastAPI Stage 1 enforce `MAX_UPLOAD_SIZE_MB=50` and `MAX_PDF_PAGES=300`, returning `413 Payload Too Large`. | *"File exceeds maximum limit (50 MB / 300 pages). Please split large manuals by chapter."* | Existing workspace state preserved. | Yes, if split into smaller files. | No |
| **`EC-005`** | **Exact Duplicate PDF Uploaded (`file_sha256` Match)** | User uploads `Paper_v1.pdf` which already exists in the workspace (possibly under a different filename). | Stage 2 detects `(workspace_id, file_sha256)` collision in `public.documents` and returns `200 OK` with `duplicate_of_doc_id`. | Toast/Modal: *"This exact document is already in your library as 'Paper_v1.pdf'."* Buttons: `[Open Existing]` or `[Force Reprocess]`. | Existing document, chunks, and widgets preserved untouched. | Optional (`Force Reprocess`). | No |
| **`EC-006`** | **100% Scanned Camera PDF** | PDF consists entirely of raster JPEG scans with 0 digital fonts (`word_count == 0` on all pages). | Stage 5 flags all pages as `needs_ocr = True`; Stage 6 processes pages in 4-page batches via `gpt-6.1-terra` Vision OCR. | Repository row shows `Vision OCR (Page 4 of 12 • 45%)` with estimated time (~12s). | Rendered OCR text blocks + page-level bounding boxes saved in `chunks`. | Automatic per-page retry. | No |
| **`EC-007`** | **Mixed Digital + Scanned/Chart PDF** | Pages 1–10 are digital text, but Page 11 is a scanned appendix and Page 12 has a raster chart. | Stage 4 extracts Pages 1–10 via PyMuPDF (\$0); Stage 5 routes **only** Pages 11 & 12 to `gpt-6.1-terra` Vision OCR. | Seamless progress; digital pages keep exact line bboxes while scanned pages get OCR bboxes. | Full hybrid chunk set preserved. | Automatic per-page retry. | No |
| **`EC-008`** | **Unsupported File Format (e.g. `.docx`, `.pptx`, `.exe`, `.mp4`)** | User drags a folder containing mixed file types into the dropzone. | Client filter + Server magic-byte check reject unsupported files with `415 Unsupported Media Type` while accepting valid `.pdf`/`.csv`/`.xlsx` files. | Unsupported files listed in a dismissible warning banner; valid files upload normally. | All valid files in the batch preserved. | Convert `.docx`/`.pptx` to `.pdf` and re-upload. | No |
| **`EC-009`** | **Network Interruption During Upload** | User's Wi-Fi drops at 65% multipart upload. | Incomplete HTTP stream times out; FastAPI never writes a partial blob to Supabase Storage or `public.documents`. | Upload tray shows `"Network interrupted — Click to resume/retry upload"`. | Browser keeps `File` reference in memory for 1-click retry. | Yes (1-click retry in UI). | No |

## 3. Domain B: Ingestion & Background Processing Edge Cases (`EC-010` – `EC-018`)

| ID | Scenario | 1. What Happens & 2. Why It Happens | 3. Application Response | 4. What the User Sees | 5. Data Preserved | 6. Retry? | 7. Admin Needed? |
|---|---|---|---|---|---|---|---|
| **`EC-010`** | **Vision OCR Failure on All Scanned Pages** | OpenAI `gpt-6.1-terra` returns repeated `503` or timeout on a 100% scanned PDF. | Worker retries 3x with exponential backoff (`flex` $\rightarrow$ `auto`). If still failing, marks `documents.status = 'failed'` and `processing_jobs.current_stage = 'running_ocr'`. | Red badge: `Failed: Vision OCR service temporarily unavailable` + `[Retry Processing]` button. | Uploaded PDF in Supabase Storage + `documents` & `document_pages` rows preserved so user doesn't have to re-upload! | Yes (resumes from Stage 6). | No |
| **`EC-011`** | **Partial OCR Failure (1 Page Fails in a 20-Page PDF)** | Page 14 is an illegible smudged scan or times out, while Pages 1–13 and 15–20 succeed. | Stage 6 marks Page 14 `ocr_status = 'failed'`, indexes the other 19 pages normally, and sets `documents.status = 'partial_ready'`. | Yellow badge: `Ready (19/20 pages indexed • Page 14 OCR failed)` + `[Retry Page 14]`. | All 19 pages' chunks, vectors, summary, and tables preserved and immediately searchable. | Yes (targeted single-page retry). | No |
| **`EC-012`** | **Embedding API Rate Limit / Failure (`POST /v1/embeddings`)** | Burst upload hits OpenAI TPM limit (`429`) or transient `500`. | `OpenAIRouterService` honors `Retry-After` header with exponential backoff (up to 4 attempts). Meanwhile, Stage 10 GIN FTS index (`tsvector`) is already committed in PostgreSQL. | Status stays `Indexing Vectors (70% • Retrying...)`; if exhausted, `Failed at Embedding` with 1-click retry. | Extracted text chunks (`public.chunks` without vectors) and OCR output preserved in DB! | Yes (resumes directly at Stage 9 without re-running OCR!). | No |
| **`EC-013`** | **Stage 11 Understanding LLM Timeout (`gpt-6-luna`)** | `gpt-6-luna` times out while generating `DocumentUnderstandingPayload`. | Retries once on `service_tier="auto"`. If still failing, populates a deterministic fallback summary (first 3 paragraphs of Page 1), sets `category = 'general_document'`, and marks `status = 'partial_ready'`. | Document is immediately searchable in RAG & PDF Studio; banner offers `[Regenerate AI Summary]`. | Storage file, chunks, embeddings, and native PyMuPDF tables 100% preserved. | Yes (`Regenerate Summary`). | No |
| **`EC-014`** | **Duplicate Concurrent Processing Jobs** | User double-clicks `Reprocess` or two worker instances pick up the same `doc_id`. | `processing_jobs` enforces an atomic PostgreSQL advisory lock / `UPDATE ... WHERE status IN ('queued', 'failed') RETURNING id` mutex. Second request is a no-op (`409 Already Processing`). | UI disables `Reprocess` button while status is active. | Active job proceeds without duplicate chunks. | N/A | No |
| **`EC-015`** | **Supabase Database / Storage Transiently Unavailable** | Network blip between FastAPI and Supabase during ingestion. | Worker catches connection error, pauses queue consumer for `5s–30s` circuit-breaker cooldown, and resumes from last committed stage checkpoint. | Status banner shows `"Reconnecting to storage..."` or queued indicator. | All previously committed stages preserved. | Automatic + manual retry. | Only if Supabase outage > 15m. |
| **`EC-016`** | **User Deletes Document While Ingestion Is Running** | User uploads a 50-page PDF and clicks `Delete` while Stage 6 (OCR) or Stage 9 (Embedding) is mid-flight. | `DELETE /api/documents/{id}` deletes the `public.documents` row immediately. Before committing any stage output, the worker checks if `doc_id` still exists (or catches FK violation `23503`), aborts remaining OpenAI calls immediately, and exits cleanly. | Document disappears from `/app/repository` immediately; zero zombie chunks left behind. | Deletion is final; in-flight worker artifacts are discarded via `ON DELETE CASCADE`. | N/A | No |
| **`EC-017`** | **User Replaces Document While Previous Ingestion Is Running** | User uploads v2 of a file and selects `"Replace Existing"` while v1 is still at 45%. | Backend increments `documents.ingestion_version` (`v1` $\rightarrow$ `v2`), cancels the `v1` job token, purges `v1` partial chunks, and starts a fresh `v2` job. If `v1` worker attempts to write, its stale `ingestion_version` guard rejects the write. | Progress bar resets cleanly to `v2` (`10% -> 100%`). | Only `v2` data is committed. | Yes | No |
| **`EC-018`** | **Worker Process Crash / Container Restart Mid-Ingestion** | Cloud container restarts during a deploy while 3 documents are in `running_ocr` or `embedding`. | On FastAPI startup, a recovery hook scans `processing_jobs` where `status = 'running'` and `updated_at < now() - interval '3 minutes'`, and automatically re-queues them from their last completed stage checkpoint! | Processing resumes automatically within seconds of server restart. | All completed stages (`document_pages`, OCR text) preserved. | Automatic on startup. | No |

## 4. Domain C: Search & AI Assistant Edge Cases (`EC-019` – `EC-028`)

| ID | Scenario | 1. What Happens & 2. Why It Happens | 3. Application Response | 4. What the User Sees | 5. Data Preserved | 6. Retry? | 7. Admin Needed? |
|---|---|---|---|---|---|---|---|
| **`EC-019`** | **Zero Relevant Search Results** | User searches for `"quantum annealing"` in a repository of accounting PDFs. | `match_document_chunks_hybrid` returns 0 rows above `min_vector_similarity = 0.28` and 0 FTS matches. | Search view shows: *"No passages matching 'quantum annealing' were found in your 12 documents."* + suggests top available topics in the repository. | Search query preserved in input box. | User can broaden filters. | No |
| **`EC-020`** | **Ambiguous / Under-Specified User Question** | User asks *"Berapa hasilnya?"* ("What was the result?") in a repository with 15 different reports. | AI Assistant identifies multiple candidate metrics across retrieved chunks, briefly answers for the top matches with `[cite:CHUNK_ID]`, and asks a clarifying follow-up chip (*"Did you mean Q3 financial net income or Lab Report #4 yield?"*). | Clarifying response with clickable document-specific follow-up chips. | Conversation thread preserved. | User clicks chip to refine. | No |
| **`EC-021`** | **Unsupported Question (Answer Not in Documents, `PR-029`)** | User asks a question whose answer does not exist in the selected document(s). | Prompt grounding contract + low-confidence retrieval flag instruct the model to explicitly abstain from guessing and summarize the closest available topic in the document. | *"Berdasarkan dokumen yang dipilih, informasi mengenai X tidak ditemukan. Namun, dokumen ini membahas Y pada Halaman 4 [cite:chk_12]."* | Conversation history preserved. | User can switch scope to `"All Repository Docs"`. | No |
| **`EC-022`** | **Conflicting / Contradictory Documents in Chat** | User asks *"What is the maximum operating temperature?"* across 2 papers where Paper A says `80°C` and Paper B says `120°C`. | Stratified retrieval pulls chunks from both papers; system prompt Rule 4 mandates presenting **both** figures neutrally with dual citations (`[Paper A • p.3]` vs. `[Paper B • p.8]`) and noting the difference. | Assistant highlights the discrepancy clearly with clickable citations to both PDFs. | Both citations saved in `message_citations`. | User can click `"Open in Synthesis Matrix"`. | No |
| **`EC-023`** | **Very Long Document (250 Pages) Broad Question** | User asks *"Summarize the main conclusions of every chapter."* | Hierarchical Context Injection combines `documents.summary` + `key_findings` + top-12 stratified chunks across pages without overflowing the 18K prompt budget. | Comprehensive structured answer with citations spanning early, middle, and final pages. | Conversation saved. | Yes | No |
| **`EC-024`** | **LLM Outputs Hallucinated or Malformed `[cite:CHUNK_ID]`** | Model outputs `[cite:chk_nonexistent]` or truncates a UUID. | Deterministic `CitationResolver` (`DOC-11`) checks every cited ID against the retrieved chunk map. Invalid IDs are stripped before sending `event: citations_verified` to the UI. If an answer made factual claims with 0 valid citations, a warning badge `"Unverified summary"` is attached. | Only 100% verified, clickable page highlights appear in the UI; zero broken links or wrong-page jumps. | Valid citations preserved. | Yes (`Regenerate`). | No |
| **`EC-025`** | **OpenAI API Rate Limit (`429`) or Model Outage (`503`) During Chat** | `gpt-6-luna` hits a transient rate limit or regional spike. | `OpenAIRouterService` retries once after `1s`; if still `429`/`503`, automatically fails over to `gpt-6.1-terra` (or vice versa) transparently! | User receives streamed answer with `< 1.5s` extra delay; if all models fail, sees `"AI service busy — Click to retry"`. | User's typed prompt and thread preserved. | Automatic failover + 1-click UI retry. | No |
| **`EC-026`** | **Long Multi-Turn Conversation (Context Overflow)** | User exchanges 40 messages in a single conversation thread. | After every 8 turns, a background `gpt-6-luna` compaction step summarizes older turns into `conversations.compacted_summary` (`~300 tokens`), keeping only the last 6 raw messages in the active prompt. | Seamless infinite conversation without latency degradation or token explosion. | Full raw message history remains visible in the UI scrollback (`public.messages`). | N/A | No |
| **`EC-027`** | **Indirect Prompt Injection Inside Uploaded PDF** | Uploaded PDF contains text attempting to hijack the assistant's instructions. | `<untrusted_document_chunk>` XML delimiters + `developer` role instruction hierarchy neutralize the directive. | Assistant treats the text as passive document content and summarizes it safely. | Audit log records request normally. | N/A | No |
| **`EC-028`** | **User Chats With a Document Still in `processing` State** | User opens a document that is at `85% (Extracting Insights)` where chunks & vectors (`Stage 10`) are already committed. | If `Stage 10` is complete, RAG chat works immediately using the indexed chunks! If `Stage 10` is not yet complete, chat input displays `"Indexing pages for AI search (65%)... Ready in ~4 seconds"`. | Clear countdown state; unlocks automatically as soon as vectors are committed. | Queued prompt auto-sends once ready. | Automatic. | No |

## 5. Domain D: Personalized Dashboard & Analytics Edge Cases (`EC-029` – `EC-037`)

| ID | Scenario | 1. What Happens & 2. Why It Happens | 3. Application Response | 4. What the User Sees | 5. Data Preserved | 6. Retry? | 7. Admin Needed? |
|---|---|---|---|---|---|---|---|
| **`EC-029`** | **Workspace Has Zero Structured/Numerical Data (`Profile 3` Qualitative Corpus)** | User uploads 15 philosophy essays or legal statutes containing 0 tables and 0 numerical KPIs. | Dashboard Engine detects `table_count == 0` and `metric_count < 3` (`DOC-14`) and switches to `Profile 3: Qualitative Corpus`. | Renders Topic Cluster Chart, Document Category Breakdown, Entity Frequency, and Key Findings Cards + honest info banner explaining how to unlock numerical charts. | Qualitative dashboard state saved. | Automatically upgrades if user later uploads a table/spreadsheet. | No |
| **`EC-030`** | **Insufficient Data for a User-Requested Chart (`< 2` Data Points, `PR-038`)** | User asks: *"Plot 5-year revenue trend"* when only 1 single-quarter report is uploaded. | `DashboardGenerationPlan` sets `data_sufficient = False` (or Gate 3 detects `len(rows) == 1`). Refuses to render a misleading 1-point trend line. | Renders an **Insufficient Data Explanation Card** showing the 1 available Q3 revenue value (`$14.2M [Q3_Report.pdf • p.4]`) and stating that Q1, Q2, and prior years are not in the repository. | Single KPI value and citation preserved. | User can upload missing reports and click `Refresh`. | No |
| **`EC-031`** | **Inconsistent Currencies or Units Across Documents (`PR-036`)** | Subsidiary A reports in `IDR (Rp Billions)` and Subsidiary B reports in `USD ($ Millions)`, or Paper A uses `wt%` and Paper B uses `mol/L`. | Validation Gate 4 (`DOC-15`) forbids `SUM()`/`AVG()` across mixed `unit_or_currency` values. Instructs SQL planner to `GROUP BY unit_or_currency` or plot dual/separate unit-labeled series. | Multi-panel or dual-axis chart with explicit currency/unit badges (`USD ($M)` vs. `IDR (RpB)`) and a warning note: *"Values are shown in their original reported currencies without FX conversion."* | Exact native numbers and units preserved without distortion. | User can filter by a single currency/unit. | No |
| **`EC-032`** | **Missing / Null Values in Extracted Table Rows** | An extracted PDF table has `N/A` or `-` for Q2 in one row. | Stage 7 table parser maps `"N/A"`, `"-"`, `""` to SQL `NULL` (never `0.0`, which would corrupt `AVG()` calculations and falsely show a drop to zero!). | ECharts renders a clean gap for `NULL` points (`connectNulls: false`) with a tooltip note `"Data not reported (NULL)"`. | Distinction between `0` and `NULL` preserved in `document_tables`. | N/A | No |
| **`EC-033`** | **Duplicate Metric Records Across Overlapping Documents** | Both `Q3_Summary.pdf` and `Q3_Full_Report.pdf` report `"Q3 2026 Operating Revenue = $14.2M"`. | SQL generation plan uses `SELECT DISTINCT period_label, numeric_value` or deduplicates by `(canonical_metric_key, period_label, numeric_value)` before summing across periods so Q3 isn't double-counted as `$28.4M`! | Accurate `$14.2M` bar for Q3 with both documents listed in the `Sources` provenance strip. | Both source citations preserved. | N/A | No |
| **`EC-034`** | **Contradictory Numerical Metrics Across Documents** | `Draft_Budget.pdf` says Q4 CAPEX is `$5.0M`, while `Final_Board_Deck.pdf` says Q4 CAPEX is `$3.8M`. | Validation layer detects two distinct `numeric_value` records for the same `(canonical_metric_key, period_label)` and sets `discrepancy_warning` on the widget. | Chart plots both bars side-by-side (`Draft_Budget: $5.0M` vs. `Final_Board_Deck: $3.8M`) with an amber **Metric Discrepancy Badge** linking to both PDF pages. | Both conflicting records preserved with full provenance. | User can exclude the draft document from widget scope. | No |
| **`EC-035`** | **Source Document Deleted Affecting Existing Dashboard Charts (`PR-018`)** | User deletes `Q3_Report.pdf` which was used by a saved dashboard widget. | `DELETE /api/documents/{id}` scans `dashboard_widgets` where `doc_id = ANY(source_doc_ids)`:<br/>• If other source docs remain, re-runs the widget's SQL.<br/>• If it was the sole source doc, sets `widget.status = 'stale_source_deleted'`. | Affected widget shows `"Source document removed"` state with `[Update Query]` or `[Remove Widget]`. | Remaining dashboard widgets stay 100% intact. | Yes | No |
| **`EC-036`** | **LLM Generates Invalid DuckDB SQL Syntax** | `gpt-6.1-terra` hallucinates a PostgreSQL-only function or misquotes a column identifier. | Gate 2 catches `duckdb.Error` and executes 1 automatic self-repair call passing the exact DuckDB error + `DESCRIBE` table schema back to `gpt-6.1-terra`. | Transparent to user (~1.5s extra latency); if repair still fails, shows `"Could not construct chart query for this request — try rephrasing"`. | Workspace tables untouched. | Yes (1-click retry or rephrase). | No |
| **`EC-037`** | **Dashboard Generation Timeout** | Complex multi-table query or slow OpenAI response exceeds `15s`. | Request aborts cleanly at `15s` timeout; DuckDB query timeout enforced at `2,000ms`. | Toast: *"Chart generation timed out. Click to retry."* | Prompt text preserved in input bar. | Yes | No |
